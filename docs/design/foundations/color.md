# 色彩

## 定位与原则

终末地的配色是**一套中性灰阶 + 一个信号色**，游戏界面在此之上再加一组分工明确的角色色。

1. **大面积只用中性色。** 白、浅灰、深灰、近黑构成全部的表面与文字。
2. **黄色是信号，不是装饰。** 它只标记行动、选中与进度。
3. **颜色有角色。** 橙、蓝、青、红、绿、紫各管一件事，不互相替代，也不拿来点缀。
4. **主题色可以接管，语义色不能丢。** 角色、活动、地区可以把黄换成自己的主题色，但危险仍然是红，成功仍然是绿。
5. **每个颜色都要对它实际所在的底色验算对比度。**

## 信号黄

![信号黄、角色色与稀有度色阶](../assets/palette/signal-and-roles.svg)

| 令牌 | 值 | 用途 | 来源 |
| --- | --- | --- | --- |
| `signal` | `#FFFA00` | 行动按钮底、当前导航项、选中环、进度填充 | 实测 |
| `signal-pressed` | `#EEEA00` | 黄色控件的按下态 | 实测（分页按钮按下） |
| `signal-deep` | `#E6DE01` | 黄底上的分隔线、更深一档的按下 | 实测 |
| `signal-ink` | `#6B5D00` | 亮色表面上"强调色作文字"时的深档 | 社区（dsh-theme-endfield） |

### 黄色只做底，不做亮底上的字

`#FFFA00` 在白底上的对比度只有 **1.11:1**，等于看不见。所以：

- 黄色作**填充**时，上面压 `neutral-900` 的墨字（15.9:1）。
- 亮色表面上需要"黄色文字"的地方，用 `signal-ink`（白底 6.6:1，`neutral-100` 上 5.9:1）。
- 暗色表面上可以直接用 `signal` 作文字（`#141414` 上 16.6:1）。

语义令牌 `accent-ink` 已经按主题切好：亮色取 `signal-ink`，暗色取 `signal`。

### 官网黄与游戏黄不是同一个值

| 出处 | 值 | 来源 |
| --- | --- | --- |
| 官网主黄 | `#FFFA00` | 实测 |
| 官网局部变体 | `#FFF500`、`#FFF000`、`#FDFD1F` | 实测 |
| 游戏内选中、进度条 | `#FCEA00` – `#FCEC00` | 社区（取色） |
| 游戏内技能树节点 | `#F7C506` | 社区（取色） |
| ReEnd 组件库 | `#FFD429` | 社区（作者取值） |
| endfield-design-skill 的"行动黄" | `#F8D34D` | 社区（作者取值） |

官网的黄偏冷、接近纯黄；游戏内的黄更暖、略偏金。本规范取官网值作为 `signal`。如果要做贴近游戏内观感的界面，可以在项目里把 `--ef-action` 覆盖成 `#FCEA00`，其余规则不变。

## 角色色

游戏界面里，黄色之外的颜色各有固定分工。以下取值来自 `endfield-design-skill` 对实机截图的取色，本仓库没有独立验证，等级为**社区**。

| 令牌 | 值 | 角色 | 不要用来 |
| --- | --- | --- | --- |
| `notice` | `#FC6C00` | 通知角标、倒计时、等级带、数量与折扣 | 表示危险 |
| `gain` | `#BCE41D` | 增益标签（`+6%`）、经验增量 | 填充进度条（进度归黄） |
| `data` | `#2A84B4` | 量值图表、流程连线 | 表示"完成了多少"（那是进度，归黄） |
| `region` | `#06A2A2` | 地区、机构的主题色 | 当通用数据色 |
| `alert` | `#F62A2A` | 危险、紧急、超支 | 当普通装饰 |
| `confirm` | `#00D872` | 确认、充裕、通用标签 | — |
| `special` | `#904EF0` | 特殊与战术物品、特定角色主题 | — |

`gain` 的社区取色范围是 `#E4FC00` – `#BCE41D`。本规范取偏绿的一端，是为了和 `signal` 拉开距离（**推断**）。

**进度与量值的区别**值得单独记：表达"完成了多少"的轨道条用黄（灰轨 + 黄填充），表达"数量有多少"的图表用蓝。

### 稀有度色阶

由低到高四档：蓝 → 紫 → 金 → 橙。

| 令牌 | 值 |
| --- | --- |
| `rarity-1` | `#24BAFC` |
| `rarity-2` | `#904EF6` |
| `rarity-3` | `#FCBA00` |
| `rarity-4` | `#FC6C00` |

用法是卡片**底部的渐变或底边条**，不是整圈描边；最高档可以在渐变上叠细斜纹。见 [卡片](../components/card.md)。

### 角色色作文字

上面的角色色是按"填充"取的，直接当文字用大多达不到对比度。需要用文字表达状态时，用按主题切好的语义令牌：

| 令牌 | 亮色 | 暗色 | 对比度（亮 / 暗） |
| --- | --- | --- | --- |
| `danger` | `#DE0909` | `#F74040` | 4.5:1 / 4.5:1 |
| `success` | `#007F43` | `#00D872` | 4.6:1 / 8.7:1 |
| `warning` | `#B74E00` | `#FC6C00` | 4.6:1 / 5.7:1 |
| `info` | `#25759F` | `#2D8FC2` | 4.5:1 / 4.6:1 |

对比度按各主题里最不利的常用表面计算：亮色是 `surface-sunken`（`#F2F2F2`），暗色是 `surface-raised`（`#1F1F1F`）。

这些值是把对应的角色色沿明度方向调到刚好达标得出的（**推断**）。状态不能只靠颜色表达，必须同时有图标或文字。

## 亮色与暗色

![亮色与暗色主题的表面层级](../assets/palette/light-dark-surfaces.svg)

官网和游戏里亮、暗两套基底都存在，都算"正统"。本规范默认亮色，在根元素上加 `data-theme="dark"` 切到暗色。

`data-theme="dark"` 与 `data-theme="light"` 也可以加在局部容器上：亮色页面里嵌一个深色版块，或者反过来。还有第三个取值 `data-theme="inverse"`，意思是"和所在的主题相反"，见下面的[反转块里的局部主题](#反转块里的局部主题)。

| 语义令牌 | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `surface` | `#FFFFFF` | `#141414` | 页面底 |
| `surface-raised` | `#FAFAFA` | `#1F1F1F` | 卡片、弹窗、浮层 |
| `surface-sunken` | `#F2F2F2` | `#000000` | 凹陷区、输入框底 |
| `surface-muted` | `#E6E6E6` | `#282828` | 悬停、激活、分页条 |
| `surface-inverse` | `#191919` | `#FAFAFA` | 反转块（标签名、强调条） |
| `ink` | `#191919` | `#FAFAFA` | 主文字 |
| `ink-secondary` | `#626262` | `#B3B3B3` | 次级文字 |
| `ink-tertiary` | `#8A8A8A` | `#8A8A8A` | 大字号或装饰性文字 |
| `ink-disabled` | `#B3B3B3` | `#626262` | 禁用文字 |
| `ink-inverse` | `#FFFFFF` | `#191919` | 反转块上的文字 |
| `line` | `#D9D9D9` | `#383838` | 分隔线、描边 |
| `line-strong` | `#B3B3B3` | `#626262` | 强调分隔、输入框描边 |
| `action` | `#FFFA00` | `#FFFA00` | 行动与选中的填充 |
| `action-pressed` | `#EEEA00` | `#EEEA00` | 按下 |
| `on-action` | `#191919` | `#191919` | 黄底上的文字 |
| `accent-ink` | `#6B5D00` | `#FFFA00` | 强调文字 |
| `accent-ink-inverse` | 同 `action` | `#6B5D00` | 反转块（`surface-inverse`）上的强调记号 |
| `control` | `#383838` | `#383838` | 中性按钮底 |
| `control-hover` | `#484848` | `#484848` | 悬停 |

亮色各值与暗色的 `#141414`、`#1F1F1F`、`#000000`、`#383838` 来自官网实测；暗色主题的其余取值是按同一套中性阶反向映射的**推断**。

中性按钮（`control`）在两个主题下取值相同：官网的深色版块里按钮仍是 `#383838`。

三个在实现组件时补上的令牌（**推断**）：

- **`accent-ink-inverse`**——`surface-inverse` 在亮色主题下是墨色、在暗色主题下是近白，压在它上面的强调记号（反转图标钮的图标、已选的复选框里的对勾）要跟着换档：亮色下直接用行动色，暗色下用强调色的文字档。它和 `accent-ink` 正好相反。整块的反转区域（面板标题带、表头带）后来改成了局部主题，里面直接用 `accent-ink`，见下面的"反转块里的局部主题"。
- **`disabled` / `on-disabled`**——官网的禁用按钮是 `#888888` 底配 `#666666` 字（实测）。这个底色在暗色页面上比正常的 `control` 还亮，所以禁用填充按主题取值：亮色取 `neutral-400`，暗色取 `neutral-850`；文字两边都是 `neutral-600`。

### 哪些颜色有意不随主题变

组件里随主题翻转的颜色一律走上表的语义令牌。只有"本来就是为某一种底色设计"的填充才直接用 `neutral-*`，在两个主题下保持不变：

| 位置 | 取值 | 理由 |
| --- | --- | --- |
| `light` 按钮 | `neutral-0` 底、`neutral-900` 字 | 规范里它就是"用在深色底上"的白按钮 |
| 圆形图标钮 | `neutral-50` 底、`neutral-900` 图标 | 要压在图像和深色版块上（官网的黑底版块里它仍是白的） |
| 分节标题的滑块 | `neutral-300` 底、`neutral-900` 箭头 | 官网：深色底上滑块保持浅灰 |
| `control` 系列 | 见上表 | 官网深色版块里按钮仍是 `#383838` |
| 资源胶囊 | `control` 底、`on-control` 字 | 游戏界面里它就是一颗深色胶囊；沿用 `control` 系列 |
| 增益签、通知角标 | `gain` / `notice` 底、`neutral-900` 字 | 角色色是按"填充 + 墨字"取的，见"色块上放什么字" |
| 日期块的小红角 | `alert` | 6px 的小三角，不承载文字 |
| 录制指示的红点 | `alert` | 8px 的圆点，不承载文字 |
| 警示条纹 | `signal` 与 `neutral-900` | 黄黑相间本身就是它的含义，换成别的颜色就认不出来了 |
| 注册色条 | `reg-magenta`、`reg-cyan`、`reg-yellow` | 印刷校准用的三原色，只做装饰 |
| 物品格的稀有度渐变 | `rarity-1` 到 `rarity-4` | 稀有度色阶是固定的角色色，只作填充 |
| 物品格"不可用"遮罩上的字 | `neutral-0` 字、`neutral-950` 垫底 | 遮罩（`scrim`）在两个主题下都是黑的 |
| 斜纹的"中"档 | `neutral-700` | 配的是 `control` 系列的深色控件 |
| 加载页 | `neutral-950` 底、`neutral-0` 字、`neutral-800` 轨道 | 官网的加载页在浅色站点上也是近黑底；它盖住整个页面，不属于任何一个主题 |
| 弹窗与抽屉的标题带 | 暗色主题的 `surface-raised`、`ink`、`line` | 官网的弹窗标题栏在浅色站点上也是 `#1F1F1F` |
| 轻提示 | `black` 80% 底、`white` 字，其余按暗色主题 | 官网的轻提示就是黑 80% 配白字（实测） |
| `strong` 的下拉面板 | 暗色主题的 `surface-raised`，当前项 `action` 底 | 官网的语言菜单是深色面板配黄色当前项（实测） |
| 展开条 | 暗色主题的 `surface-raised`、`ink-secondary`、`line`，一条 `action` 色竖条 | 官网的分享展开条是墨黑的横条配黄色竖条（实测） |
| 行带（列表的 `band` 变体、数据行带） | 暗色主题的 `surface`、`ink`、`line`；选中行反过来用亮色主题 | 游戏界面里是浅画布上的深色行，选中行白底墨字（社区） |
| 小型面积图 | `data`、`alert` | 量值图表的角色色，只作图形 |

展开条、行带和它们上面的三项做法和别的不同：它们不是逐个写 `neutral-*`，而是自己成为一个 `data-theme="dark"` 的局部主题。以标题带为例：它里面有会聚焦的关闭按钮，焦点环也得按深色底取值——整块换主题比逐个写死可靠。**一块固定深色或固定浅色的区域里还要放别的控件时，都用这个办法。**文字提示更进一步，用的是和页面"相反"的主题，见 [浮层](../components/overlay.md)。

### 反转块里的局部主题

`surface-inverse` 是"和页面相反"的一块：亮色主题下是墨色，暗色主题下是近白。面板的标题带、表格的表头带、完成横幅都是它。

问题出在这块底上**还要放别的控件**的时候。控件拿的是页面的令牌：亮色页面上，按钮的焦点环是墨色，压在墨色的标题带上看不见；已选的复选框是一个墨色方格，和带子融成一片，只剩一个对勾。逐个给它们换写法（"在反转块上用 `accent-ink-inverse`"）只管得了自己写的那几处，使用方塞进来的控件管不到。

所以反转块自己成为一个局部主题：`data-theme="inverse"`。里面照常用 `surface`、`ink`、`line`、`focus`…，取到的是按这块底色配好的值。

| 令牌 | 在反转块里取什么 |
| --- | --- |
| `surface` | 所在主题的 `surface-inverse`——这块底本身 |
| `ink` | 所在主题的 `ink-inverse` |
| `accent-ink` | 所在主题的 `accent-ink-inverse` |
| `surface-inverse` / `ink-inverse` / `accent-ink-inverse` | 所在主题的 `surface` / `ink` / `accent-ink`：反转块里的反转块就是页面的颜色 |
| 其余随主题变的令牌 | 相反主题的取值 |
| `action`、`control` 系列 | 不变：它们在两个主题下本来就相同 |

前三行保证了一件事：一块原来写着 `bg-surface-inverse text-ink-inverse` 的区域，改成 `data-theme="inverse"` 加 `bg-surface text-ink` 之后**颜色一点不变**，变的只是里面的东西。局部改过强调色的容器（下面的"主题色接管"）也照样带得进来。

和固定深色的局部主题（`data-theme="dark"`）的分工：

| | 用哪个 |
| --- | --- |
| 这块区域在亮、暗两个主题下都是深色（弹窗标题带、轻提示、行带） | `data-theme="dark"` |
| 这块区域跟着主题翻，但总和页面相反（面板标题带、表头带、完成横幅） | `data-theme="inverse"` |

两条限制：

- **反转块里不要再嵌反转块。** 它不会翻回页面的主题，而是和外面那层反转块相同。反转块里要一块和页面同色的区域，直接用 `bg-surface-inverse text-ink-inverse`；要里面的控件也跟着取值，写明 `data-theme="light"` 或 `"dark"`。
- 叶子上的反转填充不用它：键位提示、`inverse` 的标签、选中的胶囊、主行动块里面不再放别的控件，继续直接用 `surface-inverse`。

实现上（[theme.css](../../../packages/ui/src/styles/theme.css)）分两路：

- **底、字、强调色**这三对，由反转块的**父元素**对调着抄一份给它（选择器是 `:has(> [data-theme="inverse"])`）。绕这一下是因为 CSS 里一个元素读不到"自己正在改写的那个变量在父级是什么值"——在反转块自己身上写"`surface` 取 `surface-inverse`、`surface-inverse` 取 `surface`"，两个变量互相引用，都会失效。由父元素来抄，局部改过的强调色（主题色接管）自然也在里面。
- **其余令牌**取相反主题的值：亮、暗两块里各多写了一组 `--ef-x-*`，反转主题把 `--ef-*` 指过去。这一组是手抄的第二份，有一条单元测试核对它们和另一块逐项相同。

两路走的都是继承，所以取到的一定是**最近**那个主题的反面——亮、暗两个容器同时出现在页面上时也不会取错。现有的亮、暗两套取值没有动。`:has()` 在本库支持的浏览器范围内都可用（和 Tailwind v4 的底线相同）。

### 语义色作底

`danger`、`success`、`warning`、`info` 是按"文字"调的，但也可以反过来作底，上面压 `ink-inverse`：

| 底 | 字 | 亮色 | 暗色 |
| --- | --- | --- | --- |
| `success` | `ink-inverse` | 5.1:1 | 9.3:1 |
| `danger` | `ink-inverse` | 5.1:1 | 4.8:1 |

倒计时的"充裕"与"紧迫"用的就是这两组。角色色里的 `confirm` 与 `alert` 不适合这个位置：`alert` 作底时墨字白字都不到 4.5:1。

## 高对比模式

系统开了高对比模式（CSS 的 `forced-colors: active`）时，浏览器把作者写的颜色换成使用者自己定的那几种系统色：字、边线各归各的系统色，**底色一律换成页面色**，阴影直接不画。亮、暗两套令牌这时候都不作数。

这套语言里的"选中"大量靠**填充反转**表示——墨底白字的一块。底色被换掉之后，选中的和没选的就成了一个样子；用底色画出来的记号（粗条、短横、圆点）和用阴影画的环也一样，整个不见了。

所以凡是只靠底色或阴影说"选中 / 当前"的地方，高对比模式下另写一份，用**系统色关键字**。作者显式写的系统色关键字浏览器不替换，它们跟着使用者选的那套配色走。（**推断**：对应关系是按各个系统色的本义排的；画出来的样子用浏览器的 forced-colors 模拟在亮、暗两套系统配色下逐个截图核对过，没有在真的 Windows 高对比主题下看过。）

| 平时 | 高对比模式下 | 用在哪 |
| --- | --- | --- |
| 填充反转的"选中"块：`surface-inverse` 底、`ink-inverse` 字；或 `action` 底、`on-action` 字 | `Highlight` 底、`HighlightText` 字——系统的"选中项"那一对 | 分段选择的墨块、胶囊页签与筛选胶囊、楔形页签、月历的选中格与一段的两端、工具栏按下的开关钮、激活的图标按钮、已选的复选框与单选框（菱形方案相同）、开着的开关的轨道、双标签开关的旋钮 |
| 压在这种块上的记号：`accent-ink-inverse` | `HighlightText` | 复选框的勾与短横、单选框的圆点、开着的开关的旋钮、工具栏开关钮的图标、压在选中格上的"今天"短线 |
| 用底色画的"当前"记号 | `Highlight` | 页内目录的粗条、下拉与菜单当前项左缘的竖条、进度短横当前的那一根、数据行带的收藏圆 |
| 用阴影画的环 | 一圈 3px 的 `Highlight` 边线，画在里面 | 头像的选中环 |
| 连着的浅带（墨色 10%） | 上下各一条 2px 的 `Highlight` 线 | 月历里一段的中间 |
| 只靠底色表示的"移到了哪一项" | 一圈 2px 的 `Highlight` 环，画在里面 | 组合框的选项 |
| 选中又禁用：`disabled` 底、`on-disabled` 字 | `GrayText` 底、`Canvas` 字 | 分段选择、筛选胶囊、工具栏开关钮、开关 |
| 轨道上填了一段，两样都是底色 | 轨道剩一圈 1px 的线（空心），填上的那一段是 `Highlight` 的实心条 | 滑块的轨道和走过的一段（轨道的线是 `ButtonText`）；进度条、分段进度、不确定进度、加载页的进度条（轨道的线是 `CanvasText`） |
| SVG 画的环：轨道和弧同样粗，只差颜色 | 轨道收成一圈 1px 的 `CanvasText` 细线，弧是 `Highlight`、线宽不变 | 进度环（含 16px 的行内加载环） |
| 不说状态、但没了底色整个部件就看不见 | 控件自己的部件用 `ButtonText`，压在页面上的记号用 `CanvasText`；禁用的用 `GrayText` | 开关关着时轨道的边线和旋钮、滑块和它的刻度、进度短横其余的几根、月历的"今天"短线 |

规则：

- **系统色关键字只出现在 `forced-colors:` 的变体里。** 平时的颜色照旧只用令牌——这是"只用令牌"唯一的例外。
- **字压在 `Highlight` 上的那个元素，要写 `forced-color-adjust: none`。** 不写的话，浏览器会在字后面垫一块页面色的底板，把 `Highlight` 盖掉，字是 `HighlightText`、底板是页面色，读不出来。写了之后这个元素和它里面的东西不再由系统接管，所以它身上的每一处颜色——底、字、边线、焦点环——都要在 `forced-colors:` 下写成系统色。上面只有图标、没有字的（复选框、图标按钮）不用写。
- **焦点环**：画在 `Highlight` 块外面的用 `Highlight`；画在块里面的用 `HighlightText`，并且再往里收 2px（离边 4px）——贴着边的话，环和外面的页面是一个颜色，看上去只是块小了一圈。
- **"填了多少"用实心对空心说，不用两种系统色说。** 轨道和填上的那一段如果一个写 `CanvasText`、一个写 `Highlight`，在这两种颜色挨得近的配色下就分不开——浏览器模拟的亮色那一套就是近黑对深紫。轨道只留一圈线，填上的那一段是实心的，换哪套配色都分得出。
- **SVG 里写的颜色系统不换。** `<svg>` 里的 `fill`、`stroke` 写的是令牌的话，高对比模式下还是主题里的那个颜色，压在使用者自己定的页面色上可能看不清。用 `currentColor` 的（图标）会跟着字色走，不用管；写了具体颜色的，在 `forced-colors:` 下另写成系统色。
- **平时已经有形状差别的不动**：加粗的当前项（侧轨、全屏菜单、列表行、面包屑、步骤条）、格子页签的箭头块、表格选中行的复选框、时间线和步骤条带描边的节点，在高对比模式下本来就分得出。
- 纯装饰的整个去掉，见 [纹理](texture.md)。

## 主题色接管

版本、角色、地区可以有自己的主题色，把整页的强调色换掉。官网的版本日历就是例子：某个版本用红黑白，下一个版本换成冰蓝，结构不变（观察）。

实现上只需要在局部覆盖语义变量：

```css
.theme-region-wuling {
  --ef-action: #14d0d0;
  --ef-action-pressed: #10b8b8;
  --ef-accent-ink: #006a6a; /* 浅色表面上的文字档 */
  --ef-accent-ink-inverse: #14d0d0; /* 深色表面上直接用行动色 */
}

/* 暗色主题下表面的明暗反过来，两个文字档对调 */
[data-theme="dark"] .theme-region-wuling {
  --ef-accent-ink: #14d0d0;
  --ef-accent-ink-inverse: #006a6a;
}
```

规则：

- 一个界面只有一个主导主题色。
- 换的是 `action`、`action-pressed` 和两个强调文字档（`accent-ink`、`accent-ink-inverse`）；`danger`、`success`、`warning` 不动。
- 强调文字档按"所在表面是深是浅"取值，所以暗色主题下要对调，如上例。只在亮色主题下用的接管可以省掉第二段。
- 新主题色同样要过对比度：填充上压墨字 ≥ 4.5:1，文字档在所在表面上 ≥ 4.5:1。
- 主题接管时，字体、纹理也可以跟着换，不只是换色。

上例的青色取值出自 dsh-theme-endfield 的"武陵青"（社区）。

## 用法

```html
<!-- 表面与文字 -->
<section class="bg-surface text-ink">
  <p class="text-ink-secondary">次级说明</p>
  <div class="bg-surface-raised border border-line">卡片</div>
</section>

<!-- 行动：黄底墨字 -->
<button class="bg-action text-on-action active:bg-action-pressed">前往游戏</button>

<!-- 中性按钮 -->
<button class="bg-control text-on-control hover:bg-control-hover">更多情报</button>

<!-- 强调文字：自动按主题取深档或原色 -->
<span class="text-accent-ink">NEW</span>

<!-- 角色色作填充 -->
<span class="bg-notice text-neutral-900">×12</span>
```

## 宜 / 忌

**宜**

- 先用中性色把层级做出来，最后再放黄色。
- 一屏只有一个黄色的主要行动。
- 用明暗反转（黑底白字的小块）做次一级的强调，把黄色留给最重要的地方。
- 状态同时用颜色 + 图标或文字。

**忌**

- 给每张卡片加黄色描边或黄色标题。
- 在白底上用黄色文字、黄色细线。
- 把 `alert` 红当装饰色，或用 `notice` 橙表示错误。
- 用彩虹色图例。图表优先用 `data` 蓝的明度变化，其次才是角色色。
- 在组件属性里出现颜色名（`color="yellow"`）。用语义名（`variant="action"`）。
