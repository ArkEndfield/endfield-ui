# apps/site

设计文档站：把 [docs/design](../../docs/design/overview.md) 下的规范渲染成可以浏览的页面。外壳是用 [`@endfield-ui/react`](../../packages/ui/README.md) 自己的控件搭的——这个站本身就是那套规范的一个实例。

在线地址：<https://icaruszezen.github.io/endfield-ui/design/>。它和组件预览站（[apps/docs](../docs/README.md)，Storybook）是两个应用，线上一个在子路径 `design/` 下、一个在根路径。

在仓库根目录：

```bash
pnpm dev:site
```

打开 `http://localhost:6107`。改页面的代码热更新，改 `docs/` 下的文档整页刷新。

```bash
pnpm build:site
```

生成静态站点到 `apps/site/dist/`。要在本机看构建出来的样子（带着线上的那段子路径）：

```bash
pnpm --filter @endfield-ui/site preview
```

## 内容从哪来

- **正文就是 `docs/design/*.md`**，原地读，不搬、不改格式——GitHub 上照样能读。站里不另存一份。
- **目录取自 [docs/README.md](../../docs/README.md) 的"全部文档"一节**：分组、顺序、每篇后面的那句说明。加一篇文档就是在那里加一行；`docs/design` 下有文件没列进去，构建会报错。新增一个分组还要在 `scripts/content.ts` 的 `groupMeta` 里给它一个目录名和英文名。
- 文档之间的相对链接改成站内路径；指到 `docs/design` 之外的（`theme.css`、`NOTICE.md`、`packages/ui/**`）改成 GitHub 上的地址；图解拷到 `figures/` 下。
- 正文里自动加的几样，Markdown 里不用写：
  - 行内的十六进制色值前面带一个小色块；
  - 表格单元格开头的来源等级（实测 / 观察 / 社区 / 推断）画成小标签，四档的画法各不相同；
  - 宽表格在自己里面横向滚动；代码块带高亮和复制钮；二到四级标题带锚点；
  - 只放了一张图的段落变成带说明的图，点图在新标签页里打开原图。
- 正文里**不能写原始的 HTML**（要写就放进反引号或代码块），站点不渲染它，构建会报错。

## 构建时的核对

`pnpm build:site` 先核对文档，有一条不过就不出站点。也能单独跑：

```bash
pnpm check:docs
```

查两样：

1. **链接、锚点、图、索引**：相对链接的目标在不在、锚点在不在（锚点的算法和 GitHub 的一样）、图在不在、每张图解有没有文档引用、每篇文档有没有列进索引。
2. **令牌表对 [theme.css](../../packages/ui/src/styles/theme.css)**：文档的表格里，第一格是令牌名、后面跟着取值的那些行（色值、长度、时长、缓动），取值要和 `theme.css` 里的一样。亮色、暗色两格都是色值的，两个都对。

改了令牌的值、忘了改文档，或者反过来，这里会拦住。

## 怎么搭的

```
apps/site/
├── scripts/
│   ├── base.ts        站点挂在哪个路径下
│   ├── content.ts     读索引和文档，Markdown → HTML，改写链接，切搜索用的小节
│   ├── check.ts       上面说的两样核对
│   ├── document.ts    每一页的 HTML 外壳：<head>、主题的那一小段脚本、内嵌的数据
│   ├── build.ts       核对 → 打包 → 把每一页渲染成 index.html → 拷图解、写搜索索引
│   ├── dev.ts         开发服务器：每次请求现渲染
│   └── serve.ts       把 dist 按子路径起在本机上（预览和实测用）
├── src/
│   ├── Shell.tsx      外壳：侧轨 / 顶栏与全屏菜单、页脚
│   ├── DocPage.tsx    一篇文档：面包屑、页头、正文、页内目录、上一篇 / 下一篇
│   ├── Home.tsx       首页
│   ├── Search.tsx     搜索弹窗
│   ├── icons.tsx      侧轨上每一组的图标，原创的几何形
│   └── site.css       组件库的样式 + 三款开源字体 + 正文的排版
└── checks/            浏览器实测
```

- **多页的静态站**。每个路由一份完整的 `index.html`：正文、目录、标题都在 HTML 里，不开脚本也能读；页面之间是普通的链接。脚本到了之后把整页水合一次，侧轨的展开、搜索、主题切换、目录的高亮才活过来。
- **正文不重复传一遍**。页面的数据（目录、这一页的小节）是 HTML 里内嵌的一小段 JSON；正文已经在页面上了，水合前直接从 DOM 里读回来。
- **`@endfield-ui/react` 别名到组件库的源码**，和预览站是同一个做法：不用先构建组件库。服务端渲染用的那一份把依赖都打了进去，只在构建时用一下，不进产物。
- **站点挂在子路径下**：`scripts/base.ts` 里的 `base`，默认 `/endfield-ui/design/`。换地方部署用环境变量 `SITE_BASE`（首尾带斜杠）；`SITE_ORIGIN` 是写进 canonical 的域名。
- **字体打进站点**：Archivo、Outfit、Space Grotesk 三款开源字体用的是 fontsource 的包，不走外面的字体服务；中文回退到系统黑体。
- **主题**：`<head>` 里有一小段内联脚本，在样式到之前就把记着的主题（没记过就跟系统）写到 `<html>` 上，页面不会先亮一下再变暗。之后的切换和记忆是组件库的 `useTheme`。
- **图解不反色**。它们是亮底画的 SVG，暗色主题下垫在一块固定的"纸"上——是印在纸上的图，不是界面的一部分。
- **搜索**不依赖外面的服务：构建时把每篇文档按小节切开写成 `search.json`，打开搜索弹窗时才取，在浏览器里按"包含这几个词"找。中文不分词，打进去的词原样去正文里找。

## 用了库里的哪些控件

侧轨（含二级）、顶栏、全屏菜单、主行动块、面包屑、页头、页内目录、回到顶部、折叠面板（窄屏上的"本页目录"）、弹窗与输入框（搜索）、列表行、按钮、图标按钮、分节标题、统计块、提示条、镂空字、注册色条。

没有为站点改组件库：缺什么先看能不能用现成的搭。

## 浏览器实测

```bash
pnpm build:site
pnpm test:site
```

`checks/` 里是对着构建产物做的检查：每一页都渲染得出来、不报错、不横向溢出，站内的链接和图都取得到；没开脚本时正文在不在；侧轨认不认得当前页；页内目录点一项；主题切换之后重新载入；搜索；窄屏的全屏菜单；320px 宽。

- 浏览器的驱动用的是预览站实测的那一个（`apps/docs/browser-checks/lib/browser.ts`），这里只引用，写法上的讲究见 [apps/docs/README.md](../docs/README.md#浏览器实测)。环境变量 `BROWSER_PATH`、`BROWSER_FLAGS`、`CPU_THROTTLE` 同样管用。
- `SITE_URL` 改测这个地址，不起本地的静态服务：正在跑的 `pnpm dev:site`，或者线上的站点。
- CI 上没有中文字体：只断言行为（在不在、当前项是谁、溢没溢出），不断言文字的宽度和折行。

## 约束

- 站里只有原创内容：不放官方的截图、立绘、标志与字体，见 [NOTICE](../../NOTICE.md)。每一页的页脚都写着"非官方"。
- 依赖方向只有一个：`apps/site → packages/ui`。它和 `apps/docs` 互不依赖（实测引用了那边的浏览器驱动，仅此一处）。
